# RPin

RPin 是面向 Windows 10/11 x64 的轻量级 Rust 截图工具，支持区域截图、全屏截图和贴图窗口。

## 构建

需要 Rust stable（x64 MSVC）、Visual Studio C++ Build Tools 和 Windows SDK。在仓库根目录使用 PowerShell 执行：

```powershell
cargo test --locked
cargo build --release --locked
```

可执行文件生成在 `target\release\rpin.exe`。RPin 不需要额外运行时或安装程序。

## 使用

- 按 `F1` 打开区域截图。鼠标下方的窗口会高亮，单击即可选中该窗口的范围，也可以按住左键拖动自定义选区。选定范围后可以标注、贴图、保存或复制到剪贴板。截图取自触发时的桌面画面，窗口被遮挡的区域会保留当时可见的内容。
- 按 `Shift+F1` 截取鼠标所在的显示器并复制到剪贴板。
- 按 `Ctrl+Shift+F1` 截取鼠标所在的显示器并打开「另存为」对话框，默认选择 PNG，可切换为 JPEG（`.jpg` 或 `.jpeg`）。
- 按 `T` 可将选区创建为贴图；`Ctrl+T` 创建贴图并复制图像。
- 贴图窗口可拖动、缩放、调节透明度、置顶、隐藏或关闭。托盘菜单可管理现有贴图。
- 右键托盘图标可打开配置、重新加载配置、切换开机自启或退出程序。

## 截图标注

选区右下角的工具条依次提供撤销、重做、画笔、箭头、矩形、椭圆、文字、马赛克、贴图、保存和复制。再次点击当前工具可退出该工具。开始标注前可以移动或调整选区；已有标注时选区固定，避免裁剪范围变化导致标注错位。

- 点选工具后在选区内拖动。马赛克在松开鼠标后应用。
- 选中画笔、箭头、矩形或椭圆后，可在工具条选择细、中、粗（2、4、8 px）和颜色。四种工具共用线条设置，默认中线、红色。颜色支持自定义 RGB，调整只应用于接下来绘制的标注。
- 点选「文字」后在选区内单击，即可在透明文字框中输入。文字框默认随最长一行向右扩展，拖动右侧手柄可设置最小宽度，双击手柄可恢复自动宽度。只有输入或粘贴换行时才会增加行数，超出选区时可在输入框内滚动。
- 工具条上的字号（12–96 px）和颜色可在输入前或输入中调整，颜色支持自定义 RGB。按 `Enter` 换行，按 `Ctrl+Enter` 提交，按 `Esc` 取消本次输入。
- `Ctrl+Z` 撤销，`Ctrl+Y` 或 `Ctrl+Shift+Z` 重做。也可以使用工具条上的按钮。
- 「保存」在 Windows「另存为」对话框中默认选择 PNG，可切换为 JPEG（`.jpg` 或 `.jpeg`）。保存、复制和贴图均包含已提交的标注。

## 配置和日志

首次启动时，配置文件会创建在 `%APPDATA%\RPin\config.toml`，日志保存在 `%LOCALAPPDATA%\RPin\logs\`。

快捷键、通知、保存选项和贴图默认行为可在配置文件中设置。配置格式可参考首次启动生成的 `config.toml`；修改后从托盘菜单选择“重新加载配置”。

关闭选区后，RPin 默认保留 Direct2D 渲染资源 60 秒，供连续截图复用。可在已有的 `[ui]` 段中设置 `direct2d_idle_seconds = 60`，单位为秒，设为 `0` 时关闭选区后立即释放。重新加载配置后生效。

## 4K 截图性能

以下数据是 v1.1 的实测基线，来自一台 Windows x64 测试机上的真实 **3840 × 2160** 桌面，使用 Release 构建。屏幕内容、显卡驱动和系统负载都会影响结果。

### 抓屏耗时

在同一进程内对一台 4K 显示器连续抓屏 200 次，计时从发起抓屏到像素帧就绪。热运行统计排除第一次抓屏。这组基准只测抓屏，不含选区绘制、剪贴板和 PNG 保存。

| GDI 路径 | 首次 | 热运行中位数 | 热运行 P95 | 热运行最大值 | 40 ms 内完成 |
| --- | ---: | ---: | ---: | ---: | ---: |
| 直接交接 DIB（默认） | 50.97 ms | **30.51 ms** | **32.06 ms** | 42.63 ms | **198 / 200** |
| 兼容位图 + `GetDIBits`（对照） | 56.10 ms | 42.83 ms | 44.22 ms | 47.98 ms | 17 / 200 |

一次使用默认路径的 4K「全屏截图并保存」记录如下。确认路径后启动 PNG 工作线程，表中记录线程内耗时，文件选择不计入。

| 步骤 | 耗时 |
| --- | ---: |
| 准备 GDI 位图和设备上下文 | 0.08 ms |
| `BitBlt` 抓屏 | 35.57 ms |
| `GdiFlush` | 0.01 ms |
| 交接 DIB 像素 | 0.02 ms |
| **抓屏至像素帧就绪** | **35.67 ms** |
| PNG 后台编码、写入文件并释放输出帧 | 18.71 ms |

抓屏总耗时来自独立计时，分项四舍五入后可能略有差异。区域截图另测从触发到遮罩首帧的耗时。在启用了默认 60 秒释放策略的一组记录中，首次为 **149.41 ms**，复用渲染资源时为 **53.41–72.66 ms**，空闲释放后的下一次为 **100.12 ms**。

### 内存占用

一张 4K 的 32 位 BGRA 像素帧占 **31.64 MiB**。默认抓屏路径直接交接 GDI 位图，不再复制一份完整的 4K 像素缓冲。选区渲染与保存各自还会使用额外资源。

| 实测阶段 | 总工作集 | 私有提交量 |
| --- | ---: | ---: |
| 全屏保存，确认路径后持有输出帧 | 156.12 MiB | 177.29 MiB |
| 同一次保存，PNG 工作线程释放输出帧后 | 124.52 MiB | 145.67 MiB |
| 区域截图，取消选区并空闲 60 秒，释放 Direct2D 工厂后（两次记录） | 60.84–61.79 MiB | 116.69–120.65 MiB |

总工作集是进程当前驻留在物理内存中的页面，私有提交量是进程已提交的私有内存。全屏保存前后是同一进程的一对采样，两个指标都回落约 **31.6 MiB**。区域截图数据来自另一运行记录，用于说明空闲释放后的占用，不能直接与保存数据相减。

### 复测

将光标移至 4K 显示器，在可见的 Windows 桌面打开 PowerShell，从仓库根目录运行以下命令。输出包含各步耗时和首帧持有、释放后的内存数据。基准不会保存图片或改动剪贴板。

```powershell
Start-Process -FilePath .\target\release\rpin.exe -ArgumentList '--capture-bench 200 --monitor' -Wait -RedirectStandardOutput .\target\capture-4k.txt
Get-Content .\target\capture-4k.txt
```

要复测选区或 PNG 保存，在配置文件的 `[app]` 段中设置 `log_level = "debug"` 并重新加载配置。日志中的 `selection first paint`、`PNG worker finished` 和 `after releasing idle Direct2D factory` 分别记录遮罩首帧、后台保存和空闲释放后的数据。
